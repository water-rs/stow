How it works

1/3trusted build

GitHub-hosted CI compiles every crate version once and signs the artifact with cosign. Each one is keyed by crate, version, features, target and rustc, so it is only ever served to a build that would have produced the same bytes.

2/3verified fetch

The CLI verifies the signature before anything touches your target directory. A record that fails to verify is a miss, never a hit — a polluted cache can slow a build down, not change it.

3/3miss → build

A cache miss queues a build for the exact identity that missed. A crate requested on this page goes to the front of that queue, for every CI target, on the current stable rustc.

Each hit lands in your target directory as a copy-on-write clone of stow's local cache — on clone-capable filesystems (APFS, Btrfs, XFS with reflink, ReFS Dev Drive) ten projects that share a crate store its bytes once; elsewhere it is a plain copy. sccache keeps compressed entries and writes a full new copy into each target dir on every hit.
